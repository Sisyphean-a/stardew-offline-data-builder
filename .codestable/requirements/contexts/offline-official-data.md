# 离线官方数据领域上下文

该边界拥有从本机官方资产得到实体、语言、图片和官方派生关联的含义与质量规则。

## 通用语言

**实体**：由官方数据记录规范化后、以稳定 ID 写入 SQLite 的可查询记录。
_避免_：仅存在于某个原始 JSON 的临时行。

**稳定 ID**：`<entity_type>:<official source id>` 形式的实体标识；同一官方来源 ID 在不同实体类型下仍是不同实体。
_避免_：按遍历顺序生成的序号。

**事实级来源**：每条核心事实或关系都可定位到主体、字段/关系路径、事实状态、来源类别、游戏版本、来源文件与记录；跨表关联和计算还保留输入事实及可复现转换规则。本地展示覆盖与 Wiki 语义参考必须和官方事实分开。
_避免_：只用实体级文件集合证明单条事实，或把官方直接字段、官方跨表关联、可验证计算、本地展示覆盖和 Wiki 语义参考混成一种“官方来源”。

**官方派生字段**：由官方支持文件的跨表关联或可验证计算形成的玩家事实；它具有事实级来源，必要时区分“依据游戏数据整理”和“依据游戏数据计算”，不是官方原文。
_避免_：攻略、主观分类、没有官方结构化依据的推断，或人工覆盖写入官方派生区域。

**补充事实**：仅在相关官方字段、跨表关系、未识别资产、事件/地图/条件和必要的官方代码规则都无法稳定回答已确认玩家核心问题后，由 builder 独立维护的短小结构化结论。它记录来源页面修订、游戏版本、平台/语言、审核与过期状态及冲突状态，并始终与官方来源隔离。
_避免_：复制 Wiki 文本或表格、填充低价值技术字段、写入官方派生区域，或把页面存在当成事实正确证明。

**翻译状态**：实体展示文本的 `complete`、`missing`、`invalid` 或 `not_applicable` 状态。纯数字名称不能证明可展示，技术记录可明确声明不适用。
_避免_：把非空字符串一律称为完整翻译。

**实体视觉状态**：每个发布实体明确属于自身官方图片、声明的官方复用、官方无实体图片、展示代理视觉或待人工复核。自身官方图片和按名单必需图片必须正确物化；官方复用记录来源实体与理由；展示代理不计入实体自身图片覆盖；待复核不能发布。
_避免_：用空 `image_path`、`imageRequired=false`、全透明可选图或通用占位 WebP 冒充合法无图。

**玩家事实语义**：数据包为应用提供可区分的购买价、兑换成本、出售价格、获得方式、用途、地点、水域、矿井层数/层段、出现区域、制作条件、加工规则和升级条件。购买价属于带适用条件的商店报价；获得方式可细分为购买、制作、掉落、宝箱、任务或采集等来源；原始 ID 和生成参数不能仅凭字段名改写成玩家地点或获得结论。
_避免_：把所有 Price 字段叫作价格、把来源与用途混为一个方向、把 `MineBaseLevel` 直接解释为实际获取层数。

**事实状态**：固定信息不依赖玩家状态；条件信息只有在所附条件满足时成立；动态规则需要日期、进度或存档才能求值。未知表示已经调查但证据不足、冲突或无法可靠解释，暂未收录表示证据可能存在但当前资产或解析链尚未纳入，不适用由分类契约明确指定；来源、条件或推导未通过准入的候选事实拒绝发布。
_避免_：把动态规则求值成当前结论，或从 `null`、空值、`false`、`0`、`-1` 自动推断未知、暂未收录或不适用。

**人物关系边**：由官方人物资料规范化的有向关系，类型闭集为亲属、朋友、未细分亲友、监护、同住和角色配对指针；目标使用 `villager:<canonical-id>`，并保留来源、原始方向、可选称谓和适用条件。`CanBeRomanced` 是属性，`Home` 是人物到地点的条件化住所，均不是人物关系边。
_避免_：把空 `FriendsAndFamily` 标签猜成朋友，把 `LoveInterest` 写成正在恋爱，按共同住所生成同住/亲属，或自动补全反向称谓。

**玩家事实发布契约**：schema 5 / manifestVersion 2 / `player-facts-v1` 将核心事实槽、多值领域事实、关系族/有向边、条件、逐 claim 证据、视觉和查询投影作为稳定公共 API。核心问题必须有显式状态行，缺失记录不代表未知或不适用。
_避免_：继续把 `officialDerived`、任意 JSON、空值或缺失行交给应用解释。

## 稳定规则

- 现代官方 JSON、旧格式字符串和 `Strings/*.json` 联合解析；英文与官方中文优先，真实缺失与技术不适用分开记录。原始官方字段只进入构建诊断、报告或隔离证据区，应用公共契约不读取。
- 实体 ID 保持 `<entity_type>:<official-id>`；事实、关系、报价和加工规则使用不依赖中文名、数组序号、来源路径或当前值的稳定 ID。来源与记录定位去重，派生 claim 关联输入证据与稳定转换规则；所有引用启用外键并在构建、打包和安装时检查。
- `entity_cards` 和搜索文档只从规范实体与事实生成名称、别名、拼音和经审核的地点、水域、用途、获得方式、自然语言类别及最多两组行动摘要，并保留稳定命中类型；原始 ID、枚举、条件原文和高基数关系不能作为普通搜索词污染结果。
- `browse_facets` 使用版本化白名单和稳定 `scope_family + scope_id`。属于同一报价、捕获、出现、掉落或获得规则的地点、季节、时间、天气、价格与条件共享 scope，允许同维度 OR、跨维度 AND 而不拼接不同规则。facet 值记录类型/区间/单位、claim 状态、条件集合和完整性；未知、暂未收录、不适用只记录 facet family 状态，不生成具体值。
- builder 为实体名称/类型、搜索前缀、facet 文本/区间、稳定排序以及 `relations(subject,predicate,object)` 的正反查询生成并验证索引。反向索引只支持有证据的已发布关系，不生成反向事实；购买价、出售价格和兑换成本保持不同值域。
- `Data/Shops.json`、`Locations.json`、`FishPondData.json`、`Machines.json` 等支持资产只用于官方跨表关联，不独立伪造实体事实。商店金币报价按 `StardewValley.Internal.ShopBuilder.GetBasePrice` 的顺序从 `Price`、负价回退、`UseObjectDataPrice`/对象价格、利润边际与 shop/item modifier 推导；`IgnoreShopPriceModifiers` 只跳过 shop 层。可静态计算的金币额与物品兑换成本分槽、同报价 scope 和条件绑定；运行时出售价、利润边际、随机或条件 modifier 将主报价槽标为 `dynamic_rule` 并发布规则说明，绝不用对象出售价伪装购买价。只有特殊货币或物品兑换的报价没有金币购买价，主报价槽为 `not_applicable`，兑换成本仍在同一 scope；无报价、未解析或不受支持的报价才是 `not_collected`。crop 的 `SeedItemId` 只稳定关联 `object:<seed-id>`。
- `Monsters.json` 是战斗属性/掉落目录，不是出生地点表。缺失地点只能由同版本官方程序集实际创建怪物的分支投影：每个地点事实必须保留 `Stardew Valley.dll` 方法定位、完整的玩家条件、条件状态和稳定转换规则；只表示“可能遭遇”，不把怪物基础层级或目录名称猜成地点。当前版本中不作为独立可生成战斗怪物的遗留目录条目可明确为 `not_applicable`，其余未证实条目仍为 `not_collected`。
- 成就、鞋类、大型可制作物和家具等旧格式需要按有版本的官方视觉规则建立唯一图片来源、裁切矩形或 sprite 元数据；来源规范化碰撞、图集缺少确定裁切、裁切越界、资源缺失、无法解码、无效尺寸和全透明必须构成质量错误。发布清单绑定实体 ID、路径、SHA-256、实际来源、裁切矩形、视觉规则版本及复用关系，独立打包重新校验格式、解码、尺寸、透明度和哈希。
- 每个分类声明全部必需、按名单必需、展示代理或整类不适用；应有图片的名单内覆盖必须为 100%，例外逐实体解释。真实发布包生成确定性联系表与异常清单，复核全部新增/哈希变化、来源/裁切/复用/规则变化和异常候选，每个可浏览分类固定至少 5 张代表图，其余未变化图片按类抽查 5%（至少 3、至多 20）。一名具名审核者覆盖全部范围，错实体、来源碰撞、异常复用或歧义必须第二人复核；未处理待复核项阻断 `.svdata`。报告按分类及逐实体记录视觉状态、必需、物化、缺失、解码、透明、裁切、复用和复核结果。
- 发布候选的绝对门禁要求 schema/manifest/hash/外键/索引一致，核心槽、状态、条件、证据、关系、搜索/facet 投影、补充事实和视觉均无结构错误；任一条件丢失、断裂证据/关系、跨 scope facet、过期冲突补充、图片错误或待复核项都阻断 `.svdata`。
- 核心事实覆盖按“分类 × 核心槽”计算：P0 行动槽 answered≥95%、not_collected≤2%；P1 其他核心槽 answered≥85%、not_collected≤10%；稳定官方直接字段 100%/0%；人物关系组 answered≥90%、not_collected≤5%；条件 complete≥95%、opaque≤1%；名称索引、唯一卡片和 facet group 100%。`eligible` 排除契约确认的 not_applicable，answered 只含 fixed/conditional/dynamic_rule，unknown 仅计 investigated。
- 每个候选与上一个获准真实包做逐实体/槽/状态/关系/搜索/facet/视觉差异。未解释删除或状态退化阻断；单个分类槽 answered 下降超过 1 个百分点或 not_collected 增加超过 0.5 个百分点即使仍达最低线也需具名批准。分母、资格与状态变化进入审计，不能靠改 not_applicable、图片必需名单或删实体美化指标。
- 当前发布基线要求 `config.py` 中声明的官方实体类型齐全且有中文展示标签；任何缺失类型、无效翻译或数据错误都会阻断 `.svdata`。fixture 及生成的模拟官方目录只证明边界，正式验收必须用真实游戏资产构建 schema 5 包。
- 手工覆盖只能修改允许的展示/搜索字段；不得写入官方派生区域或改变事实含义，必需图片元数据不能被覆盖以规避质量门禁，覆盖名称后必须重新计算翻译状态。
- 核心事实只要发布值，就同时发布事实状态、事实级来源和条件完整性。条件完整时提供可解释语义；部分或完全不识别时保留不透明原文并明确不完整，不能降为固定信息。已支持的 `GameStateQuery` 谓词、机器输入标签/计数与价格 modifier 必须逐子句保留为类型化条件，构建器不得求值当前存档；未知子句、条件丢失、来源不可定位、推导不可复现或状态矛盾时拒绝发布相关事实。`dynamic_rule` 主槽没有直接值时必须有同实体/键的 `*_rule` 可追溯说明；未知和暂未收录可发布但必须进入覆盖报告。
- 缺口调查按单条事实依次检查实体字段与本地化、已支持官方表与跨表关系、相关未识别 JSON、日程/事件/邮件/地图/条件命令及必要的官方程序集规则，并记录检查路径和停止理由。官方直接证据和可复现官方推导优先于补充事实；冲突时补充事实失效，多补充来源冲突时发布未知。游戏版本变化后相关补充事实先待复核，复核前不得作为固定答案。补充事实由 builder 合并进统一发布契约，应用不直接读取外部来源。
- 武器 `acquisition` 默认只能由正向官方证据回答。只有 ADR 005 逐项确认的当前版本不可获得记录，才可由版本、DLL 哈希和完整解包 JSON 哈希三重绑定的官方代码否定审计标为 `not_applicable`；JSON 哈希必须使用解包根相对路径和文件字节，不能绑定本机绝对目录。任一绑定变化必须恢复 `not_collected` 并重新调查，禁止推广成自动豁免。
- 商店只有在 `Items` 中至少有一个商品或兑换材料引用能解析为已发布实体时才进入发布目录；仅包含运行时动态选项、壁纸/地板或其他未收录引用的商店不发布，避免生成无法阅读的空商店详情。
